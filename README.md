# 카드뉴스 조사 에이전트

캐리어 플랫폼 SNS 계정에 올릴 **카드뉴스 원고를, 근거를 따져 가며 자동으로 만드는
워크플로**입니다. 주제 한 줄을 넣으면 유튜브와 웹에서 자료를 모으고, 영상은 AI가
직접 보고, 품목마다 출처와 신뢰도를 매겨서, 사람이 세 번 확인한 뒤 원고를 냅니다.

n8n 워크플로 하나(노드 30개)로 돌아가며, 지금까지 실제 주제로 30번 돌렸습니다.

**요구사항 정의는 [PRD.md](PRD.md) 에 있습니다.** 문제 정의·타겟 유저·워크플로
설계·도구 계획·사람 개입 지점·MVP 와 화면 구성이 그 문서에 들어 있습니다.
`card-news-workflow-kit/` 은 과제와 함께 **받은 원본 자료**이고, PRD.md 는
그것을 읽고 제 도메인에 맞게 다시 쓴 것입니다.

---

## 무엇을 해결하려고 만들었나

캐리어(여행가방) 플랫폼을 준비하면서 SNS 계정을 먼저 키워야 했습니다. 여행
기념품·선물 같은 소재로 카드뉴스를 꾸준히 올려야 하는데, 매번 손으로 하면
이렇게 됩니다.

1. 유튜브와 블로그를 뒤져 소재를 찾는다 — **30분**
2. 그중 쓸 만한 걸 고른다
3. 진짜인지 확인한다 — 광고인지, 실제로 파는 물건인지, 가격이 맞는지
4. 카드 5~8장 분량으로 원고를 쓴다
5. 사진을 찾는다

**3번이 제일 오래 걸리고 제일 자주 건너뛰게 됩니다.** 그런데 사업 계정이라
틀린 정보를 올리면 신뢰가 깎입니다. 이 워크플로는 3번을 기계가 대신하되,
**무엇을 근거로 그렇게 판단했는지 사람이 볼 수 있게** 남기는 데 초점을 뒀습니다.

## 조사 단계는 어떻게 도나

노드 30개지만 하는 일은 여섯 묶음입니다.

### 1. 자료 모으기

유튜브(`search.list`)와 웹(Tavily)에서 각각 긁어 와 합칩니다. 한쪽이 죽어도
나머지로 진행하고, 화면에 "유튜브 0건 — 키/쿼터 확인" 처럼 이유를 적습니다.

### 2. 후보 정리

URL을 정규화해 중복을 없애고(`utm_*` 제거, `youtu.be` → `watch?v=`), 제목이
겹치는 것끼리 묶습니다. **같은 소스끼리만 묶습니다** — 안 그러면 질의어가
겹쳐서 웹 글이 유튜브 그룹에 통째로 흡수됩니다.

그다음 Claude가 후보마다 **주제 부합도 0~100점**과 고른 이유를 답니다.
유튜브는 `videos.list`로 **조회수와 길이**도 가져옵니다.

### 3. [사람] 후보 선택

유튜브와 웹을 나눠 보여주고, 각 구역에서 점수 높은 순으로 세웁니다.
1~3개를 고릅니다.

> 점수는 **주제 부합도**이지 유행 지표가 아닙니다 — 이 단계 Claude는 웹 검색을
> 하지 않고 제목·요약만 봅니다. 그래서 조회수를 따로 붙여 같은 점수일 때
> 순서를 가릅니다. 두 값을 하나로 섞지 않은 이유는, 섞으면 왜 이 순서인지
> 화면에서 설명할 수 없기 때문입니다.

### 4. 원문 확보와 영상 분석

**모델에게 "이 페이지 읽어봐"라고 하지 않습니다.** 네이버는 접근을 막고
유튜브 설명은 JS로 그려져서, 그렇게 하면 근거가 전부 "미확인"으로 떨어집니다.
그래서 우리가 직접 가져옵니다.

- 유튜브: `videos.list`로 **설명 전문**
- 웹: Tavily `/extract`로 **페이지 본문**
- 영상: **Gemini가 영상을 직접 봅니다**

마지막 것이 이 워크플로에서 제일 값이 나는 부분입니다. 쇼츠와 상당수
브이로그는 설명란이 비어 있어서, 아무리 좋은 영상이어도 거기서 나온 품목이
전부 미확인이었습니다. 지금은 이렇게 나옵니다.

```
- 크루아상 병따개 [04:00] — 프랑스에만 있는 줄 알았는데 일본에 있네…?
- 블랙빈티 (호지차 티백) [03:14] — 꼭 사야할 최애템
- 라임맛 킷캣 [10:07] — 레몬(X) 라임맛(O) 킷캣
```

품목명 + **영상 속 시각** + 실제로 한 말입니다.

### 5. 교차 검증 — 두 축으로

여기가 이 워크플로의 핵심입니다. **"믿을 만한 출처인가"** 와 **"우리가 지어낸
건 아닌가"** 는 다른 질문이라 따로 봅니다.

**근거 등급** — 품목마다 웹 검색으로 교차 확인합니다. 검색어에 **주제어를 반드시
넣습니다**(품목명만 검색하면 쇼핑몰 상품페이지만 나와 검증이 안 됩니다).

| 등급 | 뜻 | 카드에 쓸 수 있나 |
|---|---|---|
| `official` | 관광국·지자체·브랜드 공식 | 단언 가능 |
| `confirmed` | 서로 다른 출처 2곳 이상 | 단언 가능 |
| `weak` | 그런 출처 1곳 | **어디서 나온 말인지 밝혀서** |
| `retail_only` | 쇼핑몰 상품페이지만 | 추천 근거로 못 씀 |
| `unconfirmed` | 못 찾음 | 못 씀 |

**원문 대조** — 품목명이 우리가 **실제로 가져온 원문**에 글자 그대로 있는지 봅니다.
외부 서비스가 필요 없고 오탐이 없습니다.

| 판정 | 뜻 |
|---|---|
| `in_source` | 원문에 그대로 있음 |
| `head_only` | 괄호 앞만 있음 — 괄호 안은 모델 추측일 수 있음 |
| `parts_in_source` | 단어는 전부 있으나 이 이름 그대로는 없음 (모델이 조합) |
| `not_in_source` | 없음 — **카드에 쓰지 말 것** |

> 이 검사를 만든 계기는 모델이 `VC100 마스크팩 **(퀄리티퍼스트 초이스)**` 처럼
> 정식 제품명을 **추측해서 괄호로 붙이는** 버릇이었습니다. 앞부분은 원문에 있고
> 괄호 안은 지어낸 것이라, 통째로 보면 구분이 안 됩니다.

### 6. [사람] 스토리보드 승인

카드 미리보기와 함께 **영상 분석 결과 / 제품컷 후보 / 원문 대조 / 품목 교차 확인**
네 가지를 보여줍니다. 승인하면 저장, 수정 요청하면 지시를 반영해 다시 씁니다
(3회 상한).

## 연결된 도구

| 도구 | 하는 일 | 무료 한도 |
|---|---|---|
| **YouTube Data API v3** | 영상 후보, 설명 전문, 조회수·길이 | `search.list` 하루 100회 전용 버킷 |
| **Tavily** | 웹 후보, 페이지 본문 추출, 제품컷 검색 | 월 1,000 크레딧 |
| **Gemini** (AI Studio) | 유튜브 영상 직접 분석 | 하루 20회 / 분당 25만 토큰 |
| **Claude CLI** | 후보 평가, 심층조사, 스토리보드 작성 | 구독 |

**제일 먼저 걸리는 건 Gemini 하루 20회**입니다. 영상 3편씩 고르면 하루 6회
실행이 한계입니다. 실측: 17분 영상 한 편에 입력 10만 토큰.

### 도구가 실패하면

- HTTP 노드는 **3회 재시도** 후 `onError: continueRegularOutput` — 한 소스가
  죽어도 나머지로 진행하고, 읽는 쪽이 빈 값을 처리합니다
- Claude가 깨진 JSON을 주면 **파서 오류를 되먹여 2회까지 복구** 시도
- 실패는 조용히 삼키지 않고 화면과 `sources-fetched.json`에 이유를 남깁니다

### 키 취급

**API 키는 n8n Credentials에만 삽니다.** 저장소의 워크플로 JSON은 키가 빈
템플릿이고, `deploy.ps1`이 DB 사본에서 키를 이어 붙입니다.

credential은 **인증 방식이 아니라 호스트로** 맞춥니다. Tavily와 Gemini가 둘 다
Header Auth라서, 방식만 보고 고르면 **Tavily 키가 구글로 나갑니다.** 실제로 한 번
그럴 뻔했고([DECISIONS.md](n8n/DECISIONS.md) 참조) 실행 전에 걷어냈습니다.

## 사람이 개입하는 곳

세 군데이고, 전부 **되돌릴 수 없는 일 앞**에 있습니다.

| 지점 | 무엇을 정하나 |
|---|---|
| **후보 선택** | 어떤 자료로 만들지 (여기서 재료가 고정됨) |
| **질문 답변** | 독자·편집 방향이 갈릴 때만 Claude가 되물음 |
| **스토리보드 승인** | 카드 내용 확정. 수정 지시 가능 (3회) |

폼 화면이 실행을 붙잡아 두기 때문에, **고르기 전에는 다음 단계가 물리적으로
돌지 않습니다.**

## 검증

빌드할 때마다 **쓰기 전에** 세 가지를 검사하고, 하나라도 걸리면 파일을 안 씁니다.

1. Code 노드 전부 `node --check`
2. 원문 대조 판정 규칙을 fixture 8건으로
3. customCss가 n8n 검사기를 통과하는지 (걸리면 오류 없이 **조용히 잘립니다**)

그리고 **모의 워크플로**가 있습니다. 검색·폼·외부 API를 가짜로 바꿔 전 구간을
헤드리스로 돌리면서, 화면에 넘기는 폼 JSON이 n8n 규칙을 지키는지·후보 중복이
제대로 묶였는지·수정 요청 후 사진이 실제로 바뀌는지를 검사합니다.

```bash
powershell -ExecutionPolicy Bypass -File n8n\test-mock.ps1
```

무엇을 확인했고 무엇이 아직인지는 [DECISIONS.md](n8n/DECISIONS.md)의
"닫은 것 / 아직 확인하지 못한 것"에 있습니다.

## 실행

API 키 3개 발급과 credential 연결은 [n8n/README.md](n8n/README.md)에 있습니다.

```bash
# 1) n8n 켜기
powershell -ExecutionPolicy Bypass -File n8n\start-n8n.ps1

# 2) 워크플로 고친 뒤 반영 (빌드 → 키 이어붙이기 → 가져오기 → 활성화 → 재기동)
powershell -ExecutionPolicy Bypass -File n8n\deploy.ps1
```

폼: `http://localhost:5678/form/cardnews-start-form`

한 번 도는 데 **7~20분** 걸립니다. 대부분 심층조사(품목마다 웹 검색)에 쓰고,
영상 분석이 편당 30~60초 더 붙습니다.

> **n8n 창은 클릭하지 마세요.** Windows 콘솔은 창 안을 누르면 선택 모드로
> 들어가고, 그 동안 프로세스가 멈춥니다. 밖에서 보면 죽은 것과 똑같습니다.
> 출력은 `n8n/n8n.log`로 빠지니 거기서 보세요.

## 만들면서 배운 것

자세한 기록은 [DECISIONS.md](n8n/DECISIONS.md)에 있습니다. 몇 가지만.

**모델에게 검색을 맡기지 말고 재료를 직접 떠먹여야 합니다.** 첫 실키 실행에서
근거가 전부 "미확인"으로 나왔는데, 원인은 모델이 게을러서가 아니라 네이버가
차단하고 유튜브 설명이 JS로 그려져서였습니다. API로 우리가 가져오니 3/3 확보로
바뀌었습니다.

**검색어에 맥락을 넣지 않으면 엉뚱한 시장으로 갑니다.** `곤약 젤리 제품`으로
