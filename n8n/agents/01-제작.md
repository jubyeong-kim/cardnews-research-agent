# 01 · 제작 — 스토리보드를 카드 이미지로

> 먼저 `00-총괄.md` 를 읽을 것. 계약과 공통 규칙은 거기 있고 여기서 반복하지 않는다.

## 왜 제일 먼저인가

지금 `script.md` 가 나오면 **그 뒤는 전부 손이다.** 실제 노동이 여기 다 몰려
있다. 나머지 넷은 있으면 좋은 것이고 이건 없으면 자동화가 아니다.

그리고 **아직 카드를 한 장도 안 만들어 봤다.** 그래서 이 담당의 첫 일은
자동화가 아니라 **시안 몇 장**이다. 템플릿 없이 템플릿 생성기를 만들 수 없다.

---

## 무엇을 소유하는가

`runs/<runId>/storyboard.json` → `runs/<runId>/cards/*.png`

그 사이의 전부: 레이아웃, 서체, 색, 줄바꿈, 렌더링, 규격.

## 소유하지 않는 것

- **원고 문구** — 조사 단계 소유다. 본문이 길면 여기서 자르지 말고
  `build_wf.py` 의 프롬프트에 상한을 넣도록 총괄에 올린다. 디자인이 원고를
  고치기 시작하면 근거 추적이 끊긴다.
- **게시** — 05 소유. 여기는 파일까지만 만든다.
- **사진 권리 판단** — `product-shots.json` 은 후보일 뿐이다. 총괄의 저작권
  규칙을 따를 것.

---

## 입력

`runs/<runId>/storyboard.json` 의 `cards[]`. 모양은 총괄 문서에 있다.

같이 읽으면 좋은 것:
- `items-checked.json` — 판정이 `not_in_source` 인 품목이 카드에 들어가 있으면
  표시해 둘 것. 사람이 승인했어도 눈에 띄는 게 낫다.
- `product-shots.json` — 이미지 후보. **자동으로 쓰지 말 것** (아래 참조).

### 입력에서 실제로 나오는 값 (실행 46 실측)

| | |
|---|---|
| 카드 수 | 7 (역할: 표지 1 · 본문 5 · 마무리 1) |
| 제목 | 10~20자 |
| 본문 | **54~178자** ← 인스타 카드에 얹기엔 긴 편 |
| `source` | URL, `미확인`, `해당 없음` 중 하나 |
| `image_plan` | 60~120자 한국어 서술 |

**본문 길이가 제일 큰 문제다.** 178자를 1080×1350 에 읽히게 넣으면 본문 영역이
꽉 찬다. 두 가지 길이 있는데 **전자를 권한다:**
- 원고 단계에서 줄인다 (총괄에 올려 프롬프트 상한 추가) ← 근본
- 디자인이 자동 줄임 처리를 한다 ← 근거 문장이 잘릴 위험

---

## 출력

```
runs/<runId>/cards/
  01.png … 07.png        카드 번호 = storyboard 의 cards[].no
  manifest.json
```

`manifest.json`:
```json
{
  "runId": "46",
  "spec": { "width": 1080, "height": 1350 },
  "generatedAt": "2026-09-12T10:00:00+09:00",
  "template": "typo-v1",
  "cards": [{ "no": 1, "file": "01.png", "role": "표지", "bytes": 184213 }],
  "warnings": ["3번 카드 본문 178자 — 권장 120자 초과"]
}
```

`warnings` 를 비워 두지 말 것. 05 가 이걸 보고 게시 전에 사람에게 보여 준다.

---

## 만드는 순서

### 1단계 — 시안 (자동화 없음)

`design/cards.html` 에 실행 46 원고로 만든 첫 시안이 있다. **타이포만 쓰고
사진은 한 장도 안 쓴다.** 이유 둘: 남의 제품컷 권리 문제를 피하는 가장 확실한
방법이고, 우리 사진이 아직 없다.

현재 시안은 "인터넷에 흔한 형태" 라는 평가를 받았다. **여기서 할 일은 브랜드
색·서체·구조를 실제로 정하는 것**이다. 정해지기 전에 렌더링 자동화를 만들면
버린다.

시안이 답해야 할 질문:
- 표지에서 **썸네일 크기로도 읽히는가.** 인스타는 작게 먼저 보인다.
- **출처를 카드에 넣을 것인가.** 근거를 따져 만든 원고라 넣는 쪽에 한 표.
  넣으면 자리를 차지한다.
- 본문 카드가 **다섯 장 이어질 때 지루하지 않은가.** 번호·색·구조 중 무엇을
  바꿀 것인가.
- 캐리어 플랫폼이라는 **업과 연결되는 구석**이 있는가.

### 2단계 — 템플릿 고정

시안이 정해지면 HTML/CSS 를 템플릿으로 굳힌다. 지금 시안이 이미 그 모양이다 —
`CARDS` 배열과 마크업이 분리돼 있어서, 배열만 `storyboard.json` 으로 갈아끼우면
된다. 색은 `:root` 변수 한 곳에 모여 있다.

### 3단계 — 렌더링

HTML → PNG. 후보 둘:

| 방법 | 장점 | 단점 |
|---|---|---|
| **headless 브라우저** (Playwright/Puppeteer) | 시안 HTML 을 그대로 씀. 한글 줄바꿈·서체를 브라우저가 처리 | node 의존성 추가 |
| 이미지 라이브러리에서 직접 그리기 | 의존성 적음 | 한글 줄바꿈·자간을 직접 구현해야 함 |

**headless 브라우저를 권한다.** 한국어 줄바꿈은 직접 구현할 만한 게 아니고,
시안과 결과가 어긋날 여지가 없다.

n8n 안에서 돌릴지 바깥 스크립트로 뺄지는 만들면서 정할 것. 이 단계는 사람
개입이 없어서 n8n 에 넣을 이유가 약하다 — `scripts/render-cards.ps1` 로 빼고
n8n 은 Execute Command 로 부르기만 해도 된다.

### 4단계 — 연결

조사 워크플로의 `저장` 노드 다음에 붙인다. 승인 직후 자동으로 카드가 나오게.

## AI 이미지 생성은 나중에

Gemini 키가 이미 있고 이미지 생성도 된다. 하지만:

- **RPD 20 을 영상 분석과 나눠 쓴다.** 카드 7장이면 7회, 하루 두 번이면 한도다.
- 타이포 카드가 먼저 서야 비교 대상이 생긴다.
- 생성 이미지는 브랜드 일관성을 잡기 어렵다. 매번 다른 그림이 나온다.

`image_plan` 필드는 이미 스토리보드에 들어 있으니 나중에 붙일 자리는 있다.
**지금은 무시할 것.**

---

## 하지 말 것

- **`product-shots.json` 의 이미지를 자동으로 카드에 넣지 말 것.** 권리가
  해결되지 않은 후보다. Tavily 가 준 AI 설명문이 다른 제품을 가리키는 경우도
  실제로 있었다(푸치푸치 카스테라를 찾았는데 하카타 파이 상자가 나왔다).
  사람이 고른 것만 쓴다.
- **원고를 고치지 말 것.** 위 참조.
- **n8n UI 에서 노드를 고치지 말 것.** 빌더(`tools/build_make.py`)를 만들고
  거기서 생성한다. 조사 단계가 그 방식이다.

---

## 완료 판정

1. `runs/<runId>/cards/` 에 카드 수만큼 PNG 가 있고 규격이 정확하다
2. 인스타에 올렸을 때 **표지가 썸네일로 읽힌다** (실제로 올려 보고 판단)
3. 본문이 긴 카드가 잘리거나 넘치지 않는다 — 실행 46 의 178자 카드로 확인
4. `manifest.json` 이 있고 `warnings` 가 채워진다
5. 같은 `storyboard.json` 으로 두 번 돌리면 **같은 결과**가 나온다

## 시작할 때 참고

- 첫 시안: `design/cards.html` (브라우저로 열면 7장이 한 번에 보인다)
- 실제 데이터: `runs/46/storyboard.json`, `runs/46/script.md`
- 긴 본문 예시: 실행 46 의 2번 카드 (178자)
