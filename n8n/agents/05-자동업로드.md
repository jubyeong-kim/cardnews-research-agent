# 05 · 자동 업로드 — 카드를 실제로 게시

> 먼저 `00-총괄.md` 를 읽을 것.

## 왜 마지막인가

기술이 어려워서가 아니다. **되돌릴 수 없기 때문이다.**

잘못 만든 카드가 공개로 나가면 지워도 이미 본 사람이 있다. 사업 계정이라
더 그렇다. 앞의 넷은 전부 파일과 숫자만 다루고, 이 담당만 바깥에 흔적을
남긴다.

그래서 순서가 마지막이고, **만들고 나서도 한동안은 예약 없이 수동 승인으로만
쓴다.** 자동화를 켜는 건 몇 번 잘 돌아간 뒤의 일이다.

그리고 솔직히 — **02(반응 수집)는 이것 없이도 된다.** 사람이 손으로 올리고
`publish.json` 을 직접 만들면 된다. 그래서 이 담당은 "편해지는 것" 이지
"없으면 안 되는 것" 이 아니다.

---

## 무엇을 소유하는가

`runs/<runId>/cards/*.png` → 인스타 게시물 → `runs/<runId>/publish.json`

## 소유하지 않는 것

- **카드 이미지** — 01 소유. 여기서 고치지 않는다.
- **성과 읽기** — 02 소유. 게시 후는 쳐다보지 않는다.
- **댓글·DM** — 아무도 안 한다. 사람이 한다.

---

## 입력

```
runs/46/cards/01.png … 07.png
runs/46/cards/manifest.json     ← warnings 를 반드시 볼 것
runs/46/storyboard.json         ← 캡션 재료
runs/46/sources.md              ← 출처 표기 재료
```

**`manifest.json` 의 `warnings` 가 비어 있지 않으면 자동 게시하지 않는다.**
사람에게 보여 주고 승인을 받는다. 01 이 그 목적으로 채우는 필드다.

---

## 출력

```json
// runs/46/publish.json
{
  "platform": "instagram",
  "accountId": "…",
  "mediaId": "1784…",
  "permalink": "https://www.instagram.com/p/…",
  "publishedAt": "2026-09-12T19:00:00+09:00",
  "cards": 7,
  "caption": "…실제로 올린 캡션 전문…",
  "approvedBy": "사람"
}
```

**`mediaId` 가 02 의 열쇠다.** 이게 없으면 성과를 못 읽는다.
`caption` 을 전문 그대로 남기는 이유도 같다 — 04 가 나중에 캡션 형태와 성과를
붙여 보려면 원본이 있어야 한다.

---

## 캡션

카드 안 문구와 **다른 글**이다. 인스타 캡션은 검색·해시태그·더보기 접힘이
있어서 카드와 다르게 써야 한다.

재료:
- `storyboard.json` 의 `hooks[]` — 첫 줄(더보기 접히기 전)에 쓸 것
- `angle` — 한 줄 요약
- `sources.md` — 출처 표기

**출처를 캡션에 반드시 넣는다.** 근거를 따져 만든 원고인데 게시물에서
출처가 사라지면 그 노력이 없어진다. 그리고 그게 이 계정의 차별점이 된다.

`affiliate: true` 품목이 하나라도 있으면 **캡션에 제휴 콘텐츠 출처임을
밝힌다.** 총괄의 규칙이고 법적 요구이기도 하다.

---

## 알아야 할 제약

직접 확인하고 채울 것. 아래는 **아직 검증 안 된 사전 조사**다.

| 항목 | 알려진 것 | 확인 필요 |
|---|---|---|
| 계정 | 비즈니스/크리에이터 + 페이스북 페이지 연결 필요 | 02 와 같은 조건. 02 가 먼저 확인한다 |
| API | Instagram Content Publishing API. 컨테이너 생성 → 게시 2단계 | 캐러셀 절차 |
| 이미지 | **공개 URL 로 올린다.** 로컬 파일 업로드가 아니다 | 어디에 호스팅할 것인가 ← 미해결 |
| 캐러셀 | 최대 10장 | 우리는 7장이므로 여유 |
| 한도 | 24시간당 게시 수 제한이 있다 | 정확한 수 |
| 심사 | 게시 권한은 앱 심사가 필요할 수 있다 | 해당 여부 |

### 이미지 호스팅이 제일 큰 미해결

인스타 API 는 **접근 가능한 URL** 을 요구한다. 로컬 PNG 를 바로 못 올린다.
선택지:

| 방법 | 장점 | 단점 |
|---|---|---|
| 임시 공개 스토리지 | 간단 | 카드가 잠시 공개된다 |
| n8n 이 서명된 URL 로 잠깐 노출 | 통제 가능 | localhost 는 외부에서 안 보임 → 터널 필요 |
| 손으로 올리기 | 확실 | 자동화 아님 |

**이게 풀리기 전엔 손으로 올리는 게 맞다.** 억지로 터널을 뚫지 말 것 —
로컬 n8n 을 인터넷에 노출하는 건 이 프로젝트에서 감당할 위험이 아니다.

### 키

인스타 토큰은 **n8n Credentials 에만.** 총괄의 규칙 그대로다. 02 와 같은
credential 을 쓸 수 있는지 확인할 것 (권한 범위가 다를 수 있다).

---

## 안전장치 (필수)

이 담당은 다른 넷과 달리 안전장치가 **기능의 일부**다.

1. **사람 승인 없이 게시하지 않는다.** 예약 게시를 붙이더라도, 사람이 그 건을
   미리 승인한 표시(`approved.json` 같은 것)가 있을 때만 나간다.
2. **`manifest.json` 의 `warnings` 가 있으면 멈춘다.**
3. **중복 게시 방지.** `publish.json` 이 이미 있으면 다시 올리지 않는다.
   재시도로 같은 게시물이 두 번 나가는 건 흔한 사고다.
4. **드라이런이 있어야 한다.** 캡션과 카드 순서를 출력만 하고 안 올리는 모드.
   실제 게시 전에 이걸로 먼저 본다.
5. **삭제 기능을 만들지 않는다.** 지우는 건 사람이 앱에서 한다.

---

## 하지 말 것

- **승인 없는 자동 게시.** 위 참조.
- **게시물 삭제·수정 API 구현.** 만들지 않으면 실수로 부를 일도 없다.
- **로컬 n8n 을 인터넷에 노출.** 호스팅 문제를 그렇게 풀지 말 것.
- **카드 이미지 손보기.** 01 소유. 크기가 안 맞으면 01 에 올린다.
- **출처 빼고 올리기.** 근거를 따진 이유가 없어진다.

---

## 완료 판정

1. 드라이런이 캡션과 카드 순서를 정확히 보여 준다
2. 실제 게시가 **한 번** 된다 (중복 없음)
3. `publish.json` 이 남고 **02 가 그걸로 성과를 읽는다** — 이게 진짜 판정이다
4. `warnings` 가 있는 건이 자동으로 멈춘다
5. 같은 건을 두 번 실행해도 두 번 안 올라간다

## 시작할 조건

- 01 이 카드 PNG 를 내고 있을 것
- 02 가 계정 형태를 확인해 뒀을 것 (같은 조건이라 02 가 먼저 부딪힌다)
- **이미지 호스팅 방법이 정해졌을 것** ← 지금 제일 막혀 있는 곳

그 전까지는 **사람이 손으로 올리고 `publish.json` 을 직접 쓴다.** 그래도
02·03·04 는 전부 돌아간다.
