# 04 · 유행 조사 — 무엇이 먹히는 형태인가

> 먼저 `00-총괄.md` 를 읽을 것.

## 왜 네 번째인가 — 그리고 솔직한 경고

이 담당은 **자동화 값이 넷 중 제일 낮다.** 처음 제안은 "카드뉴스의 현 유행
형태를 조사한다" 였는데, 그건 기계가 잘 못 하는 일이다.

- 인스타 인기 게시물은 **API 로 못 긁는다.** 해시태그 검색 API 는 막혔고,
  남는 건 스크래핑인데 약관 위반이고 계정이 걸린다. 같은 구글 계정에
  YouTube·Gemini 키가 걸려 있으므로 위험이 한 곳에 몰린다.
- "요즘 이런 포맷이 유행" 은 **수치로 잘 안 잡힌다.** 사람 눈이 낫다.
- 남의 유행보다 **내 계정 데이터가 정확하다.** 팔로워가 다르고 주제가 다르다.

그래서 이 담당의 일을 **바꿔서 정의한다.**

> ~~남들이 뭘 하는지 조사한다~~
> → **내 데이터에서 무엇이 먹혔는지 읽어 다음 기획에 넣는다**

남의 유행 조사는 **사람이 릴스 보다가 캡처해서 넣는 쪽**이 빠르고 정확하다.
이 담당은 그걸 **받아 적는 자리**만 마련한다.

---

## 무엇을 소유하는가

`library.sqlite`(03) + 사람 메모 → `library/playbook.md`

**`playbook.md` 가 이 담당의 유일한 산출물이다.** 조사 단계의 스토리보드
프롬프트에 들어가는 지침이 된다.

## 소유하지 않는 것

- **숫자 수집** — 02 소유
- **표** — 03 소유
- **원고 작성** — 조사 단계 소유. 여기는 지침만 준다.

---

## 입력

### 1. 성과 (03 의 표)

```sql
-- 저장수 기준 상위/하위 실행
SELECT r.run_id, r.topic, MAX(m.value) saves
FROM runs r JOIN metrics m USING(run_id)
WHERE m.metric='saves' GROUP BY r.run_id ORDER BY saves DESC;
```

**표본이 몇 건인지 항상 같이 적을 것.** 3건으로 "이 포맷이 낫다" 는 말을 하면
안 된다. 다음 문장 형태를 쓸 것:

> 저장수 상위 3건 중 3건이 표지에 숫자를 넣었다 (전체 8건 중 5건이 숫자 표지,
> 즉 숫자 표지 5건 중 3건이 상위). **표본 8건, 결론이라기엔 이르다.**

### 2. 사람 메모

```
library/notes/2026-09-12.md
```

사람이 릴스·피드 보다가 적어 두는 자유 형식. **정해진 틀을 강요하지 말 것** —
틀이 생기면 안 적는다. 담당은 이걸 읽어 playbook 에 반영하기만 한다.

### 3. 원고 특징 (표에서 뽑을 수 있는 것)

`storyboard.json` 에서 기계로 셀 수 있는 것들:
- 카드 수, 본문 평균 길이
- 표지 제목에 숫자가 있는가
- `hooks` 중 어느 것을 표지에 썼는가
- 품목 근거 등급 분포
- `affiliate: true` 품목이 있었는가

이걸 성과와 붙여 본다. **상관이지 인과가 아니다.** 표에 그렇게 적을 것.

---

## 출력 — `playbook.md`

```markdown
# 카드뉴스 지침  (갱신: 2026-10-01 · 표본 12건)

## 확인된 것
- 저장수는 좋아요보다 주제 적합도를 잘 나타낸다 (표본 12, 상관 …)
- 표지에 숫자가 있는 편이 저장수가 높았다 (숫자 7건 중 5건이 상위 절반)

## 시도 중 (근거 부족)
- 카드 6장이 8장보다 나은가 — 표본 3건. 판단 보류

## 사람 메모에서
- (2026-09-20) 여행 카드뉴스는 "가격" 을 표지에 박는 게 요즘 많음

## 조사 단계 프롬프트에 넣을 문장
- 표지 제목에는 가능하면 숫자를 넣어라 (개수·가격·기간)
- 카드는 6장을 기준으로 한다
```

**마지막 절이 실제로 쓰이는 부분이다.** 나머지는 근거를 남기는 자리다.

### 프롬프트에 반영하기

`playbook.md` 의 마지막 절을 `build_wf.py` 의 스토리보드 프롬프트에 넣는다.
**자동으로 넣지 말 것.** 사람이 읽고 옮긴다. 이유: 프롬프트가 자동으로 바뀌면
원고 품질이 왜 변했는지 추적이 끊긴다. 자동화 값보다 추적 값이 크다.

---

## 하지 말 것

- **인스타 스크래핑.** 약관 위반이고 계정이 걸린다. 위 참조.
- **표본 3건으로 결론 내리기.** 표본 수를 항상 적을 것.
- **상관을 인과로 쓰기.** "숫자 표지라서 저장이 많다" 가 아니라 "숫자 표지인
  것들이 저장이 많았다" 로 적을 것.
- **playbook 을 프롬프트에 자동 주입.** 위 참조.
- **남의 게시물 문구·구성을 그대로 옮기기.** 총괄의 저작권 규칙이 여기에도
  적용된다. 형식은 참고하되 선택·배열을 베끼지 말 것.

---

## 완료 판정

1. `library/playbook.md` 가 있고, **모든 주장에 표본 수가 붙어 있다**
2. 마지막 절의 문장이 실제로 `build_wf.py` 프롬프트에 들어갔고, 그 전후
   원고를 사람이 비교해 봤다
3. 사람 메모 자리(`library/notes/`)가 있고 실제로 쓰이고 있다
4. 표본이 적을 때 **"모른다" 라고 적혀 있다** — 이게 제일 중요하다

## 시작할 조건

**게시물 성과가 최소 5~10건 쌓이기 전에는 시작하지 말 것.** 02 가 돌기 시작해
데이터가 모일 때까지 이 담당은 할 일이 없다. 그동안 `library/notes/` 폴더만
만들어 두고 사람이 메모를 쌓게 하는 게 전부다.
