# 03 · 자료 축적 — 흩어진 실행을 조회 가능한 표로

> 먼저 `00-총괄.md` 를 읽을 것.

## 왜 세 번째인가

**데이터는 이미 다 있다. 조회가 안 될 뿐이다.** `runs/` 에 실행 폴더가 40개
넘게 쌓여 있는데 "오사카 다룬 적 있나?" 에 답하려면 폴더를 열어 봐야 한다.

반나절짜리 일이고, 끝나면 두 가지가 바로 된다: **같은 주제 또 조사하지 않기**,
**같은 품목 또 쓰지 않기**.

02 뒤에 두는 이유는 성과 데이터가 들어와야 표가 완성되기 때문이다. 다만
성과 칸을 비워 둔 채 먼저 만들어도 된다 — 의존이 약하다.

---

## 먼저: 벡터 DB 를 만들지 말 것

처음 제안에 "스키마나 벡터에 가중치" 가 있었다. **방향은 맞고 도구가 과하다.**

지금 품목 수를 세어 보면 실행 40여 건 × 회당 5~7품목 = **많아야 200개대**다.
200행에 벡터 DB 를 붙이는 건 못 박으려고 포크레인 부르는 일이다. 유지비만 들고
질의는 더 느려진다.

**SQLite 파일 하나면 된다.** 파이썬에 기본으로 들어 있고, n8n Code 노드에서도
읽을 수 있고, 사람이 DB 브라우저로 직접 열어 본다.

벡터가 값을 하기 시작하는 지점은 명확하다: **"코로로 젤리" 와 "코로로 구미"
를 같은 것으로 묶어야 할 때.** 지금 규모에서는 정규화된 이름 일치 + 별칭 목록
몇 줄로 95% 잡힌다. 수천 개를 넘고 별칭 목록이 손으로 감당이 안 될 때 다시
꺼내면 된다. **그때 바꾸기 쉽게 조회를 함수 하나로 감싸 둘 것.**

---

## 무엇을 소유하는가

`runs/*/` 전부 → `library/library.sqlite`

## 소유하지 않는 것

- **`runs/` 안의 파일** — 읽기만 한다. 원본은 각 단계 소유다.
- **판단** — "이 품목 또 쓸까" 는 04 와 사람이 정한다. 여기는 "전에 썼다" 는
  사실만 제공한다.

---

## 표 모양

작게 시작한다. 부족하면 칸을 더하면 된다. 처음부터 다 넣으면 절반이 빈다.

```sql
-- 한 실행 = 한 행
CREATE TABLE runs (
  run_id      TEXT PRIMARY KEY,   -- n8n 실행 번호
  topic       TEXT,               -- 입력한 주제
  purpose     TEXT,               -- 용도와 독자
  period_days INTEGER,
  researched_at TEXT,             -- ISO8601
  cards       INTEGER,
  published_at TEXT,              -- publish.json 있으면
  permalink   TEXT
);

-- 한 품목 = 한 행. 같은 품목이 여러 실행에 나오면 행도 여럿.
CREATE TABLE items (
  run_id     TEXT NOT NULL,
  name       TEXT NOT NULL,
  name_norm  TEXT NOT NULL,       -- 공백·문장부호 제거, 소문자. 중복 판정용
  item_type  TEXT,                -- 제품 | 장소
  evidence   TEXT,                -- official | confirmed | weak | retail_only | unconfirmed
  verdict    TEXT,                -- in_source | head_only | parts_in_source | not_in_source | no_source
  affiliate  INTEGER,             -- 0/1
  used_in_card INTEGER,           -- 실제로 카드에 들어갔으면 카드 번호, 아니면 NULL
  PRIMARY KEY (run_id, name_norm)
);

CREATE TABLE item_sources (
  run_id    TEXT NOT NULL,
  name_norm TEXT NOT NULL,
  url       TEXT NOT NULL,
  host      TEXT
);

-- 성과. 02 가 채운 metrics/*.json 을 옮긴다. 없으면 비어 있어도 된다.
CREATE TABLE metrics (
  run_id  TEXT NOT NULL,
  day     TEXT NOT NULL,          -- YYYY-MM-DD
  metric  TEXT NOT NULL,          -- reach | saves | likes | …
  value   INTEGER,
  PRIMARY KEY (run_id, day, metric)
);
```

**`name_norm` 이 핵심이다.** 원문 대조에서 쓰는 것과 **같은 정규화**를 써야
한다 — `build_wf.py` 의 `JS_VERDICT` 안 `norm()` 이 그것이다. 두 곳이 다르게
정규화하면 "원문에 있다" 와 "전에 썼다" 가 서로 다른 이름을 가리킨다.
**정규화 규칙을 복사하지 말고 한 곳에서 가져다 쓸 것.**

### 별칭

```sql
CREATE TABLE aliases (canonical TEXT NOT NULL, alias_norm TEXT PRIMARY KEY);
```

사람이 손으로 채운다. 자동으로 추론하지 말 것 — 잘못 묶으면 조용히 틀린다.
이게 나중에 손으로 감당이 안 될 때가 벡터를 검토할 때다.

## 채우는 법

실행 폴더에서 읽는다:

| 표 | 출처 파일 |
|---|---|
| `runs` | `storyboard.json` (audience/angle), `publish.json` |
| `items` | `storyboard.json` 의 `items[]` + `items-checked.json` 의 `verdict` |
| `items.used_in_card` | `storyboard.json` 의 `cards[].body` 에 품목명이 있는지 |
| `item_sources` | `storyboard.json` 의 `items[].sources[]` |
| `metrics` | `metrics/*.json` |

**전부 다시 읽어도 되게 만들 것.** 증분 갱신을 먼저 만들지 말 것 — 40개 폴더를
통째로 다시 읽는 데 몇 초면 되고, 증분은 어긋나면 찾기 어렵다.
`python tools/build_library.py` 한 번에 처음부터 다시 만드는 방식이 맞다.

**과거 실행에 없는 필드가 있다.** `items-checked.json` 은 최근에 생겼고,
`parts_in_source` 판정은 더 최근이다. 없으면 NULL 로 두고 넘어갈 것.

## 쓰이는 곳

만들고 나면 이런 질문에 답한다. **실제로 이 질문들이 답이 되는지로 검증할 것.**

```sql
-- 이 주제 전에 다룬 적 있나
SELECT run_id, researched_at, cards FROM runs WHERE topic LIKE '%오사카%';

-- 이 품목 전에 썼나
SELECT r.run_id, r.topic, i.used_in_card
FROM items i JOIN runs r USING(run_id)
WHERE i.name_norm = ? AND i.used_in_card IS NOT NULL;

-- 자주 나오는데 한 번도 카드에 못 들어간 품목 (근거가 약해서 밀린 것들)
SELECT name, COUNT(*) n FROM items
WHERE used_in_card IS NULL GROUP BY name_norm HAVING n >= 3 ORDER BY n DESC;

-- 근거 등급별로 성과가 다른가 (04 가 볼 것)
SELECT i.evidence, AVG(m.value) FROM items i
JOIN metrics m USING(run_id) WHERE m.metric='saves' GROUP BY i.evidence;
```

**마지막 질의가 이 담당의 존재 이유다.** `official` 근거로 쓴 카드가 실제로
더 저장되는지 — 지금은 아무도 모른다.

## 조사 단계에 되먹이기

표가 서면 조사 워크플로가 이걸 읽어서:
- 후보 화면에 **"이 품목은 실행 38에서 이미 썼습니다"** 를 띄운다
- 심층조사 프롬프트에 최근에 쓴 품목 목록을 넣어 피하게 한다

**되먹이기는 표가 실제로 정확한 걸 확인한 뒤에 붙일 것.** 틀린 표로 후보를
거르면 좋은 재료를 조용히 버린다.

## 하지 말 것

- **벡터 DB·임베딩 API.** 위 참조. 규모가 오면 다시 얘기한다.
- **`runs/` 에 쓰기.** 읽기 전용이다.
- **증분 갱신 먼저 만들기.** 통째로 다시 읽는 게 지금 규모에 맞다.
- **정규화 규칙 복사.** 한 곳에서 가져다 쓴다.
- **`library.sqlite` 커밋.** `.gitignore` 에 `*.sqlite` 가 이미 있다. 언제든
  다시 만들 수 있으므로 커밋할 이유도 없다.

## 완료 판정

1. `python tools/build_library.py` 로 `runs/` 전부가 표에 들어간다
2. 위 질의 네 개가 **실제로 답을 준다**
3. 두 번 돌려도 같은 결과다 (멱등)
4. 필드가 없는 옛 실행에서 터지지 않는다

   몇 개를 이전 실행과 대조해 손으로 확인할 것
