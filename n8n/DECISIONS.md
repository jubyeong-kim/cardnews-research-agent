- **Convert to File + Read/Write Files 노드 조합이 불필요해졌습니다.** `NODE_FUNCTION_ALLOW_BUILTIN=fs`가 태스크 러너로 전달되는 것을 설치본 소스(`n8n/dist/task-runners/task-runner-process-js.js:87`)에서 확인하고 실제 실행으로 검증했습니다. 노드 9개를 아꼈습니다.

- **노드 수 18 → 21개.** 래퍼 출력 파싱 노드와 폼 필드 생성 노드가 추가됐습니다.

## 구현 중에 잡은 버그 2개

1. **Code 노드 샌드박스에 `URL`·`URLSearchParams`가 없습니다** (`ReferenceError`, 실측 확인). `new URL()`을 쓴 URL 정규화가 `try/catch`에 삼켜져 **조용히 전부 무력화**됐습니다. 증상: `utm_source`가 안 지워지고 `youtu.be` 링크가 같은 영상과 병합되지 않음. 문자열 기반 정규화로 교체했습니다. `test-mock.ps1`이 이 회귀를 검사합니다.

2. **래퍼의 JSON 추출이 "첫 `{` ~ 마지막 `}`"였습니다.** Claude가 JSON 뒤에 문장이나 두 번째 블록을 붙이면 너무 많이 집어와 파싱이 깨졌습니다(간헐적). 중괄호 짝을 세는 방식으로 바꾸고, 본문을 PowerShell의 JSON 파서에 통과시키지 않고 그대로 넘겨 n8n의 `JSON.parse`가 판정하도록 했습니다.

## 실키 첫 실행에서 잡은 버그 3개 (2026-09-09)

API 키를 넣고 실제로 돌리자 모의 데이터로는 보이지 않던 것들이 나왔습니다.

3. **12개 상한이 웹 소스를 통째로 삭제했습니다.** 유튜브가 25건을 먼저 Merge에 밀어넣으니 `groups.slice(0,12)`가 전부 유튜브로 채워졌습니다. 첫 실행 결과가 `{유튜브: 12}`인데 오류는 0건 — 조용히 사라진 것입니다. 소스별 라운드로빈으로 교체해 `{유튜브: 6, 웹: 6}`이 됐습니다. PRD의 "다양성 확보" 요구와 직결됩니다.

4. **Claude가 긴 중첩 JSON에서 간헐적으로 괄호를 흘립니다.** 스토리보드(카드 6~8장)에서 발생했습니다. 처음엔 "같은 내용을 다시 출력하라"로 재시도했는데 그것도 실패했습니다 — 실패한 그 어려운 작업을 반복하는 것이라 당연했습니다. **파서의 실제 오류 메시지와 깨진 텍스트를 돌려주고 그 부분만 고치게** 바꾸니 통과했습니다(최대 2회). 재생성보다 수리가 쉬운 작업입니다.

5. **`node -e`로 넘긴 JS의 큰따옴표가 PowerShell에서 사라집니다.** 검증기가 아예 실행되지 않았습니다. `scripts/json-check.js` 파일로 분리해 해결했습니다. 이때 넣어둔 "검증기 실행 불가" 가드가 이 사고를 JSON 오류로 위장하지 않고 정확히 잡아냈습니다 — 판정을 종료코드가 아니라 stdout으로 실어보낸 것이 맞는 선택이었습니다.

부수 사항:

- **Tavily는 같은 질의에 간헐적으로 빈 결과를 줍니다.** 동일 요청 2회를 연속 보내 0건 / 14건을 확인했습니다. 파라미터 문제가 아니므로 워크플로는 유튜브만으로 진행하되, 후보 화면의 **소스 상태** 줄에 사유를 표시합니다. 두 HTTP 노드에 `retryOnFail`(3회)도 걸어뒀습니다.
- **Tavily 결과는 `published_date`가 대체로 비어 있습니다.** 기간 필터는 서버에서 적용되지만 화면에는 "날짜 미확인"으로 표시됩니다. 유튜브는 전부 날짜가 옵니다.
- **Tavily가 네이버 블로그를 실제로 잡아옵니다** (`m.blog.naver.com`, `blog.naver.com`). 네이버 API를 뺀 대가가 우려보다 작습니다.
- Tavily가 한두 단어짜리 빈약한 항목("기념품")을 섞어 보내므로 제목 6자·본문 20자 미만은 버립니다.

## n8n 2.x 발행 모델 (2026-09-09, 재부팅 후)

- **`active` 플래그만으로는 폼이 열리지 않습니다.** n8n 2.x는 draft / published를 구분하고, `workflow_published_version`에 행이 있고 `workflow_entity.activeVersionId`가 채워져야 프로덕션 webhook이 등록됩니다. 부팅 로그의 `Processed 0 draft workflows, 0 published workflows`가 그 신호입니다. UI에서 눌러야 하는 것은 **Publish**이며, 예전의 Active 토글이 아닙니다.
- **`import:workflow`는 `active`를 파일 값으로 덮어씁니다.** 버그를 고칠 때마다 재import하는 동안 활성 상태가 계속 꺼졌습니다. 앞으로는 워크플로를 재import하지 말고, 바뀐 Code 노드 내용을 UI에서 붙여넣는 편이 안전합니다. Credentials 연결도 같은 이유로 보존됩니다.
- **`npx n8n`은 매번 최신을 재해석해 약 1GB를 다시 받습니다.** 재부팅 직후 부팅이 몇 분간 멈춘 원인이었습니다. `n8n@2.38.5`처럼 버전을 고정해도 소용없습니다 — npx는 캐시를 스펙 문자열 기준으로 나눠서 `n8n`과 `n8n@2.38.5`가 다른 슬롯입니다. `start-n8n.ps1`은 npx 캐시에 이미 풀려 있는 실행 파일을 직접 호출하고, 캐시가 없을 때만 npx로 내려받습니다.
- **한글이 든 `.ps1`은 UTF-8 BOM으로 저장해야 합니다.** PowerShell 5.1이 BOM 없는 스크립트를 ANSI로 읽어 `罹먯떆` 같은 깨짐이 납니다. 세 스크립트 모두 BOM을 붙였습니다.

## 브라우저 첫 실행에서 잡은 것 (2026-09-10)

- **폼 주소는 `path`가 아니라 `webhookId`로 등록됩니다.** 노드에 `path: "cardnews"`와 `webhookId: "cardnews-start-form"`을 둘 다 넣었는데 n8n은 후자를 경로로 씁니다. 실제 주소는 `/form/cardnews-start-form`. 확인 방법은 DB의 `webhook_entity` 테이블이고, 추측하지 말고 거기서 읽으면 됩니다.
- **`claude -p`는 WebFetch·WebSearch를 기본 차단합니다.** 그래서 심층조사가 원문을 한 번도 열지 못하고 모든 카드의 근거가 "미확인"으로 나왔습니다. 모델은 정직하게 미확인으로 표시했으므로 PRD의 안전장치는 작동한 것이고, 빠진 것은 권한이었습니다. `ask-claude.ps1`에 `--allowedTools WebFetch WebSearch`를 넣어 해결했습니다. Bash와 파일 쓰기는 주지 않았습니다.
- **`용도와 독자`는 검색어에 반영되지 않습니다.** 편집 판단(후보 평가·독자·앵글·후킹)에만 쓰이고 검색은 `주제` 값만 씁니다. 의도한 분리이지만, 사용자가 목적지("오사카")를 독자 칸에 적으면 검색 결과가 전 세계로 흩어집니다. placeholder가 순수 독자 정보만 예시로 보여준 탓이 큽니다. 지역은 `주제`에 넣어야 합니다 (`오사카 기념품 추천`).
- **어제 강제 종료된 n8n이 살아남아 SQLite를 점유하면 `Database ping failed`가 납니다.** DB 손상처럼 보이지만 아닙니다. `start-n8n.ps1`이 포트 5678 점유를 먼저 확인하고 거부하도록 가드를 넣었습니다.

그래서 `선택 정리` → `유튜브 원문` → `웹 원문` 노드를 추가해 **우리가 본문을 가져와 프롬프트에 붙입니다.** 유튜브 쇼츠는 설명이 0자인 경우가 있어 제목만 남는다는 점은 감안해야 합니다.

**품목 교차 검증** (사용자 제안). 본문에서 품목명을 뽑고 각각을 웹에서 다시 찾아 확인합니다. 두 가지가 핵심입니다.

1. **검색어에 주제어를 반드시 붙입니다.** 품목명만 검색하면 쇼핑몰 상품페이지만 나와 검증이 되지 않습니다. `코로로 젤리` → `코로로 젤리 오사카 기념품 추천`으로 바꾸니 출처가 11번가·쿠팡에서 마이리얼트립·트립스토어·matcha-jp 같은 여행 매체로 바뀌었습니다.
2. **등급 기준을 명시합니다.** confirmed(블로그·기사 2곳 이상) / weak(1곳) / retail_only(쇼핑몰만) / unconfirmed(못 찾음). 카드 본문의 주장 근거로는 confirmed와 weak만 허용합니다.

효과가 측정됩니다. 같은 품목 4개에 대해 품목명만 검색했을 때는 **4개 전부 confirmed**였고, 주제어와 등급 기준을 넣으니 confirmed 1 / weak 1 / retail_only 1 / unconfirmed 1이 됐습니다. 특히 `라이스 워시오프팩 (케아나나데시코 모공 쌀팩)`처럼 **괄호 안 정식 제품명을 모델이 추측해 붙이던 것**이 "이 품명 자체를 다룬 출처 못 찾음"으로 바뀌었습니다. 그래서 프롬프트에 "정식 제품명을 추측해 괄호로 덧붙이지 마라"를 명시했습니다.

**제휴·광고 탐지도 넣었습니다.** 실제 후보 영상 설명에 "이 포스팅은 네이버 쇼핑 커넥트 활동의 일환으로, 판매 발생 시 수수료를 제공받습니다"와 `#광고`가 있었는데 초기 프롬프트는 이를 짚지 않았습니다. 이제 제휴 표기가 보이면 해당 품목에 `affiliate: true`를 달고 카드의 한계에도 적게 합니다. SNS 계정 운영 용도라 중립적 큐레이션처럼 보이면 안 됩니다.

`build_wf.py`에 **Code 노드 JS 문법 검사**를 넣었습니다 (`node --check`, top-level return이라 함수로 감싸서). 프롬프트를 손댈 때마다 문자열 이스케이프가 깨지는데, 전에는 3분짜리 실행 끝에 `Unexpected string`으로만 드러났습니다. 실제로 이 검사가 도입 직후 `저장` 노드의 오류를 즉시 잡았습니다.

**중복 묶기는 같은 소스끼리만 합니다.** 소스를 안 가리면 제목이 질의어("여행 기념품 추천")에서 많이 겹쳐 웹 글이 유튜브 그룹에 흡수되고, 웹 소스가 통째로 사라집니다. 어제 넣은 회귀 검사가 이걸 잡았습니다.

## 유튜브 영상 분석 (2026-09-10)

설명란이 비어 있는 영상 문제를 고칩니다. 쇼츠와 상당수 브이로그는
`snippet.description` 이 사실상 비어 있어서, 영상 내용이 아무리 좋아도 거기서
나온 품목이 전부 미확인으로 떨어졌습니다. Gemini 에 유튜브 URL 을 그대로 넘기면
화면과 말을 직접 읽습니다.

| 항목 | 값 | 확인 방법 |
|---|---|---|
| 엔드포인트 | `POST https://generativelanguage.googleapis.com/v1beta/interactions` | 공식 문서 quickstart 의 curl 예시 |
| 인증 | 헤더 `x-goog-api-key` | 같은 예시 |
| 리비전 | 헤더 `Api-Revision: 2026-05-20` 로 못 박음 | 2026-05 파괴적 변경으로 출력이 `steps[]` 로 이동. 안 박으면 배포된 워크플로 밑에서 또 바뀔 수 있음 |
| 영상 전달 | `input: [{type:'text'...}, {type:'video', uri:'https://www.youtube.com/watch?v=...'}]` | 영상 이해 문서 |
| 응답 모양 | **최상위가 JSON 배열** `[{...},{...}]` (chunked 스트리밍) | 키 없이 실제 호출 |
| 응답 위치 | 배열 전체를 훑어 `steps[].type === 'model_output'` 의 `content[].text` 를 이어 붙임 | 문서 + 모의 응답 회귀 검사 |
| 무료 한도 | 하루 유튜브 8시간, **요청당 영상 1개**, 공개 영상만 | 영상 이해 문서 |

### 응답이 배열이라 HTTP 노드를 텍스트 모드로 둡니다

키 없이 호출해 보니 오류가 `[{"error":{...}}]` 로 왔습니다. 배열입니다.
`generateContent` 는 객체 하나를 주는데 이쪽은 다릅니다 (`Transfer-Encoding:
chunked`). 없는 경로는 404 를 주므로, 배열은 경로 오류가 아니라 이 엔드포인트의
실제 모양입니다.

설치본 소스(`HttpRequestV3.node.js`)를 보니 기본값에서는

```js
if (Array.isArray(response)) { response.forEach((item) => returnItems.push(...)) }
```

즉 **최상위 배열을 아이템 여러 개로 쪼갭니다.** 그대로 뒀으면 영상 2편을 보냈는데
응답 아이템이 5개로 나와 `영상 분석 대상` 과의 인덱스 짝이 조용히 어긋났을
것입니다 — 엉뚱한 영상의 분석이 다른 후보에 붙는 종류의 버그입니다.

그래서 `options.response.response.responseFormat = 'text'` 로 둡니다. 같은 소스에서
텍스트 모드는 호출당 정확히 아이템 하나를 `{data: '<원문>'}` 로 냅니다. 배열
해체는 `심층조사 지시` 안에서 직접 합니다. 객체 하나로 오는 경우도 함께 받습니다.

**요청당 1개 제한 때문에** `영상 분석 대상` 노드가 영상마다 아이템 하나를
내보내고, HTTP 노드가 각각 한 번씩 호출합니다. 그래서 고른 영상이 3편이면
호출도 3번, 시간도 3배 듭니다 (편당 30~60초).

**상한 두 개.** 최대 3편(후보 선택 상한과 같음), 40분 초과는 건너뜁니다.
유튜브 URL 은 구간을 잘라 보낼 수 없어서 2시간짜리 브이로그를 넣으면 하루
한도를 크게 깎습니다. 건너뛴 영상도 설명 전문은 그대로 쓰이므로, 이 상한은
지금까지의 동작으로 되돌아갈 뿐 잃는 것이 없습니다.

**영상 분석 결과는 `source-text.txt` 에 같이 들어갑니다.** 이게 중요합니다.
`원문 대조`가 그 파일로 품목명을 확인하므로, 따로 뒀으면 Gemini 가 화면에서
직접 본 품목이 `not_in_source` 로 잘못 찍혔을 것입니다.

**키가 없어도 워크플로는 돕니다.** 노드가 `onError: continueRegularOutput` 이고
`심층조사 지시`가 응답을 못 읽으면 `videoErrors` 에 적고 넘어갑니다. 실패 내역은
`runs/<실행번호>/sources-fetched.json` 의 `videoErrors` / `videoSkipped` 에 남습니다.

### 같이 고친 것 — credential 추론이 키를 엉뚱한 곳으로 보낼 뻔했습니다

`tools/reapply.py` 는 새 HTTP 노드에 credential 을 **인증 방식으로 추론**해
붙였습니다. Tavily 와 Gemini 가 **둘 다 Header Auth** 라서, 그대로 뒀으면 Gemini
노드에 Tavily credential 이 붙어 `Authorization: Bearer tvly-...` 를
`generativelanguage.googleapis.com` 으로 보냈을 것입니다. 401 로 끝나는 게 아니라
**남의 서비스에 우리 키가 나가는** 문제입니다.

이제 같은 인증 방식의 credential 이 **정확히 하나일 때만** 추론하고, 여럿이면
비워 둔 채 어느 노드인지 이름을 찍어 경고합니다. 틀린 키를 붙이느니 비워 두는
편이 낫습니다.

`test-mock.ps1` 에 남아 있던 `npx --yes n8n` 도 고쳤습니다. 다른 두 스크립트에서
이미 잡았던 1GB 재다운로드 버그가 이 파일에만 남아 있었습니다.

## 아직 확인하지 못한 것

- **브라우저에서의 전체 왕복.** 헤드리스 검증은 폼 노드를 Code 노드로 치환해 돌린 것입니다. 실제 폼 렌더링, 체크박스 3개 초과 차단, 새로고침 유지, 제출 버튼 두 번 누르기, n8n 재시작 후 대기 복구는 **브라우저에서 직접 확인해야 합니다**. 소유자 계정과 Credentials는 2026-09-09에 설정 완료.
- **need_input 질문 분기.** 실키 실행 두 번 모두 Claude가 되묻지 않고 바로 스토리보드를 냈습니다. 질문 경로는 모의 데이터로만 통과했습니다. 독자가 갈리는 주제를 넣어 한 번 확인하는 게 좋습니다.
- **스토리보드 수정 요청 분기.** 헤드리스 검증은 항상 '승인'을 제출했습니다. 수정 루프는 아직 실행되지 않았습니다.
- **`$('노드').first()`의 루프 시 실행 회차 의미.** 스토리보드는 이 의존을 피해 디스크(`storyboard-latest.json`)를 경유하게 했지만, `응답 파싱`이 참조하는 `심층조사 지시` 컨텍스트는 여전히 `.first()`입니다. runDir·sessionId·candidates가 회차와 무관해 문제되지 않을 것으로 보지만 실측은 안 했습니다.
- **Gemini 성공 응답의 실제 모양.** 키 없이 호출해 엔드포인트 존재, 인증 헤더
  이름, `Api-Revision` 수용, 오류가 배열이라는 것까지는 확인했습니다. 하지만
  **성공 응답은 아직 못 봤습니다.** 청크가 몇 개로 쪼개지는지, `output_text` 가
  실제로 붙어 오는지, 모델 이름(`gemini-3.5-flash`)이 무료 등급에서 되는지는
  키를 넣고 한 번 돌려 봐야 압니다. 파서는 배열/객체·조각/통짜를 모두 받도록
  해 뒀지만, 확인한 것과 대비해 둔 것은 다릅니다.
- **긴 출력.** Execute Command의 stdout은 10MB에서 **앞부분이 조용히 잘립니다**. 후보 12개·카드 8장 규모면 안 걸리지만, 넘치면 래퍼가 파일로 쓰고 경로만 반환하도록 바꿔야 합니다.
